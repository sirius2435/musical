# Scala / React 课程开发规范 V2

让代码符合项目已采用的课程标准，保持输入、业务步骤、持久化边界和页面结构可检查。使用中文说明设计与审查结果。先确定适用范围，再读取资料并编码；不要事后才套检查清单。

## 依据与适用边界

- [rules.txt](references/rules.txt) 是完整保留的 60 条规范原文。每次处理适用的课程代码任务前读取，保留其强制、推荐、允许和条件性表述。不能删改原文或通过概括收紧条文。
- [课程手册](references/course-handbook.md) 来自用户提供的 Lec3–Lec5 整理内容，用于解释概念，不能覆盖具体规范。未获得原始课件，不声称核验过原课件页码。
- 实现时先检查当前仓库说明、约定、依赖、代码和用户任务。采用已有技术栈；参考手册不授权更换框架、数据库、部署方式或 API 协议。已有代码与明确采用的规则冲突时，在任务范围内修正，不能仅因它已存在就认定合规。
- 示例是模式参考，不是全项目脚手架，不得覆盖既有契约。保持现有身份类型、JSON 形态和路由名称，除非任务明确要求迁移。
- [来源与冲突记录](references/sources-and-conflicts.md) 区分原始规则、用户提供的手册、本次 V2 明确要求、samples 事实和推荐方案。Lec2–Lec5 原始文件未取得，不能编造课件引文、页码或把示例当作课程授权。
- 本次 V2 明确要求 Scala 使用 val、禁止 var 和命令式 for、不使用传统 try/catch/finally。`Try[T]` 仍可用；IO 的 for/yield 与命令式循环必须区分，Resource 是有样例依据的推荐资源方案，不宣称课件强制指定。细节与差异先读 Scala 风格和冲突记录。
- 领域身份和有限状态有明确类型；不要求把所有 String/Int 包装成类型。Zustand 按本次要求定位于跨页面共享的核心数据，优先私有 Store 与 get/use/set；具体函数名和签名不必机械一致。不因课程术语强制独立部署微服务。

## 六阶段执行

1. **任务分析**：识别语言、课程项目身份和涉及的模块，读取上表对应资料及仓库约定、配置和依赖。普通 Python、无关算法题不加载 60 条及前后端 references，也不强加 IO、Message、Tailwind 或禁用该语言的异常语法。混合任务同时读取前后端规范，但 Python 辅助脚本仍遵循其语言约定。
2. **设计**：先确定数据模型、输入响应、服务和表归属、可信身份、重要副作用、事务连接及页面状态。核对适用的 60 条；保持已有技术选型和线格式。冲突记录中有未决事项时采用已说明的暂行方案，报告限制；只有影响当前任务且无法安全推进时才询问。
3. **编码**：按 Scala 风格和模块模式实现。消息为独立 final case class，构造参数承载输入，唯一必要入口 plan(connection): IO[Response]。可以调用任何服务公开 plan 或 Table def，私有 utils 不跨服务。受保护路由先把 token 转可信身份；每表独立定义与初始化，私有 SQL 紧邻公开 IO 方法之前。前端按业务区域组织、Hooks 维护核心状态、纯函数推导展示数据，Tailwind 为项目样式标准。
4. **自查**：按检查清单核对实际修改文件、职责与数据流，区分强制项、推荐项和待确认项。检查不必要的抽象或转发层、重复状态及编码禁令。规则 52 的 class + send 是推荐，不能擅自变成唯一允许的调用形式。
5. **验证**：从项目配置选择相关编译、类型检查、lint、测试和构建；检查真实请求响应、鉴权和状态行为。对未执行的检查记录原因，不用静态搜索或编译通过替代全部行为验证。
6. **交付**：说明变更、验证结果和未解决问题，审查意见附具体位置、来源编号及 Critical/Major/Minor。推荐问题不冒充强制违规；只读审查不自动变成全项目重构。

## 审查与交付

具体问题报告“规则编号、文件位置、问题、最小修复”；区分规范违规、条件未满足、推荐改进和验证不足。用户只要求审查时，不直接批量修改项目。

交付说明改了什么、关键契约、运行过的验证及剩余限制。对权限、事务、序列化和异步页面验证实际行为；只改文档时不要求运行整个应用。

维护本 skill 时可运行 [包校验脚本](scripts/validate_skill.py)。该脚本检查包元数据、引用、60 条编号及原文一致性，不检查业务项目是否合规。更新规则副本必须来自用户明确提供的新版本。

在本 skill 目录执行 `python3 scripts/validate_skill.py`；仍保留原始规则文件时，可追加 `--rules-source 原始规则文件路径` 进行逐字节比较。脚本只依赖 Python 标准库。
